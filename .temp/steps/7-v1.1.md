# Etapa 7 — v1.1

Fecha compactação, reviewer e tools de workspace.

**Aceite:** compact some da linha do work; `EVENTS` fica. `reviewer` só com workflow on.

## Plano

1. `compact_comments` é composite: `load` (view comments) → modelo resume → `commit` emite `compact`.
2. Action `compact`: comment-resumo + apaga os comments do alvo. `EVENTS` não apaga. `comment.delete` só o alvo.
3. Agent `reviewer` depth 1, ceiling da §9.1, só se workflow on.
4. `directory` / `workspaces` se houver muitos roots ou mais de um workspace.

## Implementação

### Núcleo

- Mesmo contrato. `shape = composite` só informa. Duas calls do mesmo `name`.
- Hidratar `views = ["comments"]` no `load`.
- Action `compact` + `comment.delete`: lote único, só aquele `work_id` / `request_id` / `inbox_id`.
- Próximo assemble: último comment = resumo.
- Ceiling do stage `review`: deny de write/counter como no exemplo da §5; agent `reviewer`.
- Sem workflow: `reviewer` não entra no effective.

### Pasta

```text
tools/compact_comments/tool.toml    shape = composite, views = ["comments"]
tools/directory/tool.toml           se v1.1 precisar
tools/workspaces/tool.toml
```

### Testes

- Load → output = comments. Commit → um resumo, os outros comments daquele work apagados, `EVENTS(compact)` + events antigos intactos.
- Replay do work ainda mostra os comments apagados no log (`type = comment` / `compact`).
- Workflow on com etapa review: run do `reviewer`, sem `fs.write`.
- Workflow off: `reviewer` ausente.
- Compact de outro `work_id` no emit: recusa.
